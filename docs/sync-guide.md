# 跨设备同步使用说明

首版面向 Windows。局域网直接发送，WebDAV 暂存最近上传的加密内容，接收设备可离线并稍后拉取。不维护全部历史的一致性，不传播本地删除；缓存满后淘汰最早上传的投递。接收内容进入 QcClip，默认同时写入系统剪贴板，可直接按 Ctrl+V 粘贴。

## 从哪里开始

同步设置主页显示同步状态、设备名称、添加设备入口、连接方式摘要和已添加设备。点击“添加设备”打开侧边抽屉，在“附近设备 / 远程添加”页签之间切换；进入附近设备后自动开始查找。连接设置使用独立抽屉，通过“局域网直连 / WebDAV”页签展示完整表单；每台设备的范围、格式和限制在“设备设置”抽屉中调整。同一时间只有一个抽屉，不使用嵌套抽屉或多层展开。关闭抽屉不会取消配对，可从主页面继续；附近搜索仍受 5 分钟时限约束。

每台设备只有一套设备 ID、公私钥和信任列表。局域网、WebDAV 共用配对结果；切换网络或通道不需要重新添加。两种通道独立启停，同时可用时优先局域网。添加设备不会自动开启同步，也不会发送已有历史。

主页的“接收后写入系统剪贴板”默认开启，对局域网和 WebDAV、自动与手动接收均生效，历史和收藏内容都可直接粘贴。关闭后仅保存到 QcClip。批量拉取时系统剪贴板保留最后完成接收的内容，不按跨设备时间排序；重复拉取已接收事件、迟到的旧内容事件不会反复写入。接收写回不会被当作本机新增重新同步，也不增加本机捕获、粘贴次数。若系统剪贴板写入失败，会通过全局通知提示，已接收的内容仍保留，可在 QcClip 中手动复制。

## 同一网络：发现附近设备并添加

1. 两台电脑打开“设置 → 跨设备同步”，按需修改设备名称。
2. 两端都点击“添加设备”，进入“附近设备”，无需配置 WebDAV，无需开启同步总开关。
3. 在其中一台的附近设备列表中找到对方，点击“添加”。对方会收到统一通知，并在页面显示本次请求的 6 位配对码。
4. 在发起方输入对方屏幕上的 6 位码，点击“验证并请求添加”。不需要交换长设备码，也不用填 IP。
5. 对方看到验证通过后，确认是自己的设备，点击“确认添加”。发起方自动获得确认，双方“我的设备”均出现对方。
6. 开启两端页面顶部的同步开关后开始同步。局域网默认可用；如果之前关闭了局域网通道，可在“连接设置”中开启。

附近搜索与可发现状态持续 5 分钟，可提前结束。仅搜索期间广播设备自报名称、公钥、端口和临时发现标识，不广播配对码、私钥或剪贴板。发现不代表已认证；只有密码验证及接收方人工确认后才保存信任。

单个请求 3 分钟有效，6 位码每次随机生成。使用 SPAKE2 密码认证密钥交换，认证结果与本次请求及双方完整身份绑定，再用认证加密确认；不能从抓取的验证流量离线枚举 6 位码。每个请求最多 3 次认证尝试、每次搜索窗口最多接收 6 个新请求。取消会释放对端请求；确认响应丢失时发起方自动重试。接收方完成后临时保留确认查询，避免关闭搜索导致发起方无法获得结果。

## 不同网络：远程添加

1. 打开“添加设备 → 远程添加”，点击“配置 WebDAV”，双方填写同一个已存在、允许读写的目录及账号，保存并测试连接，再返回远程添加。无需开启局域网或同步总开关。
2. 一台点击“生成配对码”，另一台输入四组、共 16 个字符的临时码，点击查找。码不区分大小写，可省略连字符和空格，有效期为 5 分钟。
3. 输入方检查设备名称，确认添加；再由生成方点击“检查连接请求”。双方核对六位核对数字一致后，生成方确认添加。
4. 双方启用 WebDAV 和同步总开关。设备显示 WebDAV 表示可使用云端缓存，并不表示对方此刻在线。以后在同一网络也可改用局域网，无需重新配对。

WebDAV 在添加阶段只负责交换加密身份资料。短码需要共同目录，并非专属 WebDAV 身份。六位核对数字用于核对身份，不是这里的 16 字符配对码，也不同于附近添加时的一次性密码。

配对码可取消；生成方完成或过期后清理云端邀请。异常退出可能留下加密对象，但过期邀请不会被接受；重新打开应用需生成新码。请求通过按钮检查，不持续轮询 WebDAV。

## 高级：交换设备码与连接设置

远程添加中的“备用方式：交换完整设备码”保留通用资料交换方式。通过可信文件或复制粘贴互相提供设备码，核对指纹并各自添加一次。默认设备码不含 IP；“连接设置 → 局域网直连”可复制附带地址的设备码。完整码比临时码长，普通添加流程不需要手抄它。

局域网 UDP 发现固定使用 39827 端口；TCP 直连默认使用 39827，可在“连接设置 → 局域网直连”修改 TCP 监听端口。Windows 防火墙须允许 QcClip 在所用网络接收连接；不同 Wi-Fi、访客网络隔离、禁广播或端口被占用时，附近发现可能失败。仅使用局域网无需配置 WebDAV。配对期间临时监听身份验证请求，即使同步总开关或局域网同步通道关闭，也不会接受剪贴板同步。

对已有信任设备，同网可自动寻找地址；跨网段或广播受限时，可以在设备策略填写对端 IP:端口。目标两种通道可用时优先 LAN；LAN 不可用或发送失败时，可将内容上传到已启用的 WebDAV 缓存，接收端避免重复入库。

## WebDAV 上传与拉取

1. 在“连接设置 → WebDAV”填写双方共用的已存在、允许读写的目录地址、账号与密码，保存并测试连接。仅使用 WebDAV 时可关闭局域网，不需要填写 IP。
2. 配对完成后启用 WebDAV 和同步总开关，确认双方设备策略允许 WebDAV。
3. 自动上传与自动拉取分别控制：可自动上传、手动拉取，也可完全手动或自动收发。自动上传按设备策略逐条处理本地新增，不等待合并；目标已通过 LAN 成功收到时不重复上传。
4. 开启 WebDAV 后，主窗口标题栏显示紧邻的一组快捷按钮：标题栏位于顶部或底部时横向排列，左侧“上传最近一次内容”，右侧“拉取新内容”；标题栏位于左侧或右侧时纵向排列，上方上传，下方拉取。最近一次本机复制或新增历史上传到对方历史，最近一次本机新增收藏上传到对方收藏；两者取最后一次操作，悬停提示显示类型和内容摘要。此记录随数据库保存，重启后保留；远程接收、切换页面、选中、置顶、排序及编辑标签备注不会改变上传目标。目标删除或取消收藏后不会改发另一种类型，需再次复制或新增收藏。首次启用这项记录后，同样需先完成一次本机新增操作。
5. 上传指定条目可在右键菜单“跨设备同步 → 上传到 WebDAV”中选择目标，即使对方离线也可上传；“发送到设备”仍优先 LAN。两者都遵循所在列表：从历史发送就进入对方历史，从收藏发送就进入对方收藏，并携带标签、备注。标题栏上传直接使用 WebDAV 并面向所有允许的已添加设备，只上传一条。同步总开关关闭时按钮不可用；手动操作不受自动上传、自动拉取开关影响。手动拉取也可使用同步主页的“拉取新内容”；提示“正在接收”不表示所有附件已经下载完成，手动检查会顺延下一次自动检查。

拉取会逐条检查缓存。不支持的消息类型、字段缺失、解密失败或条目校验失败只跳过对应条目，其他有效内容继续接收；通知会分别说明安排接收和跳过的数量。索引文件整体损坏时，无法读取该发送设备的缓存，但仍会检查其他设备。遇到格式无法识别，先确认双方均已更新并重启到同一版程序；仍失败的内容可在发送端重新上传。无需为单条错误清空整个 WebDAV 目录。跳过的条目不会标记为已接收，更新版本或重新上传后仍可重试。

### 拉取速度与请求额度

提供节省请求（60 秒）、快速同步（2 秒）、手动拉取预设，点击即应用；也可填写 1–86400 秒自定义间隔并保存。自建 WebDAV 可使用快速同步，不受坚果云额度硬限制。

正常空闲检查每个其他发送设备只发一次 GET，不刷新租约、不重复建目录、不扫描目录、不查询 ack。两台设备均为 60 秒时，合计约 60 次 / 30 分钟；均为 2 秒时约 1800 次。用户提供的坚果云限额为 600 次 / 滚动 30 分钟，上传、资源下载、配对、测试和清理还需额外计数，应按实际服务选择间隔。

主页显示本次运行中本机近 30 分钟请求数（重启后重新计数），抽屉显示本机空闲检查估算。它们不是账号总用量，不能据此判断供应商剩余额度。关闭自动上传及自动拉取后，正常空闲期间无 WebDAV 请求；仅关闭自动拉取时，本地新增仍会触发已开启的自动上传。

上传成功表示已写入云端，对方可稍后拉取；不表示对方已入库。遇到服务器限流，上传与拉取统一遵循 Retry-After 冷却；自动拉取网络失败会逐步退避。

### 缓存范围

每台发送设备独立维护一份索引，默认最多 100 次目标投递、原始资源总量 100 MiB。向多台设备投递分别计数。可在 WebDAV 抽屉调整条数和容量；先达到任一上限就淘汰最早上传的投递，索引本身也有 4 MiB 上限。容量按原始字节计算，实际服务端空间还包括编码、加密和元数据开销。

较小内容直接放在加密索引中，大资源作为独立加密对象。接收后保留云端缓存，反复拉取及重启不会重复下载已接收资源或重复入库；本地修改、删除不改云端缓存。设备很久不拉取，可能错过已淘汰内容；可以在来源端重新手动上传所需条目。这不是全量同步或完整备份。

服务端需支持 MKCOL、PUT、GET、DELETE；连接测试还使用 PROPFIND Depth:1。配置地址所指父目录必须事先存在，QcClip 在其下创建 qcclip-v1/indexes 和 qcclip-v1/objects，不递归创建配置地址缺失的父目录。地址不得包含账号密码、查询参数或片段，重定向分享链接不能作为 WebDAV 地址。HTTP 和 HTTPS 均可使用；HTTP 不加密 WebDAV 账号密码和访问路径，HTTPS 可保护这些信息的传输过程。

缓存内容按目标设备端到端加密，其他目标不能解密。服务端仍可观察对象大小、时间和访问关联。

## HTTP 地址与本地测试

HTTP 地址不限于本机或局域网；自用服务器可直接填写 IP 或域名，不要求配置证书。HTTP 会明文传输 WebDAV 账号密码和访问路径，网络链路上的第三方可能读取这些信息；剪贴板载荷仍由应用端到端加密。建议为 WebDAV 使用独立密码，并在可以配置时优先使用 HTTPS。

本地测试服务器须支持 WebDAV，而不只是提供普通文件下载。地址中的目录由服务器根目录映射决定：例如根目录为 `test-webdav-data` 时，使用 `/QcClipSync/` 前需建立 `test-webdav-data/QcClipSync` 文件夹；也可直接使用服务器根地址。填写该服务器配置的测试账号密码，并保持服务器运行。

测试连接会实际创建 QcClip 目录并验证索引目录的 WebDAV 响应；HTTP 401 提示认证失败，409 提示父目录缺失，503 提示服务暂不可用或访问受限。两端测试同步时应指向同一服务器目录，并使用配对码或完整设备码建立双方信任。

## 每台设备的策略

打开对应设备的“设备设置”抽屉，分别选择自动历史、收藏新增、重复触达、连接通道、文本、富文本、图片、自定义格式、文件引用或实际文件内容。默认使用兼容优先格式策略，图片允许发送，文件内容和路径引用默认关闭。可切换常规格式，或排除具体格式，格式写法为 namespace/key，多项用 ` | ` 分隔。

这些范围主要控制向该设备自动发送的内容；关闭自动历史/收藏不会阻止一次明确的手动发送。阻止设备或关闭所有通道会阻止连接。接收端还独立执行文件内容开关及资源大小限制。

单张图片、单个文件和条目文件总量均有上限。资源超限时不会以预览图或路径冒充已发送的内容。内部格式、失败格式和虚拟文件整体不发送；部分发送会在设备结果中注明。HTML 中的外部图片不会被同步服务自动下载。

## 手动发送

在条目右键菜单的“跨设备同步”中选择操作和目标：

- 上传到 WebDAV：只上传指定条目，等待目标拉取。
- 发送到设备：优先局域网，按当前格式策略发送，更新相同来源身份并保留未发送格式。

历史与收藏去向由发送时所在列表决定，不根据条目是否同时被收藏猜测。接收方已有相同内容时复用条目，补充对应的历史或收藏关系，不移除另一种关系。

两种入口均携带标签与备注。不存在的标签自动创建，同名标签复用，保留接收方已有标签；发送方无标签或备注不会清空接收方数据。接收方没有备注时填入，已有不同备注时保留并通过全局通知提示。菜单不再提供单独发送收藏元数据或替换全部格式。

目标若有本地修改，接收端拒绝覆盖并显示冲突原因。需在接收设备自行处理本地冲突，再重新发送；首版没有强制覆盖。全部可用设备包含允许连接且局域网在线，或本机已启用 WebDAV 的配对目标；WebDAV 目标无需此刻在线。

自动同步不传播删除、取消收藏、排序、置顶和已有条目的编辑。接收内容不会回环广播，也不会增加接收设备的本机捕获次数。

同步收到的历史和收藏使用 QcClip 图标，悬停显示“应用名称 · 来自设备”；没有应用名称时只显示“来自设备”。来源应用名称随加密内容发送，不传输原应用图标和程序路径，也不增加图标上传、下载请求。转发时保留应用名称，设备指本次发送方。已有本机捕获来源优先显示，本机再次复制后使用本机来源。来源也支持搜索，移除配对不会清空已接收内容的来源。

接收入库后仅局部更新受影响的列表行，保留滚动位置、当前选中、多选和其他行缓存。历史或收藏收到新内容时，不重载另一种列表；同一内容同时存在于两处时，只更新对应行的共享内容、收藏状态、标签和备注。连续接收会合并处理，拖动排序或页面加载期间延后应用，不打断当前操作。新增标签补入标签栏，不清空标签筛选。

## 操作反馈

保存设置、复制配对码/设备码、测试连接、检查请求、附近添加请求、验证码操作、添加或移除设备，以及手动发送的最终结果，使用项目统一的全局通知。网络操作在后台执行，处理期间禁用相关按钮，避免重复提交。

附近添加请求使用信息通知，完成添加使用成功通知。常规自动收发、心跳与后台重试更新设备状态和页面错误，不逐条弹通知；备注冲突会额外通知用户。LAN 手动发送成功表示收到接收端确认；WebDAV 成功明确表示已上传、对方可稍后拉取，不表示已入库。手动拉取的后续资源错误同样使用全局通知。

## 文件和数据目录

启用实际文件内容后，发送方读取普通文件快照并校验读取期间是否变化；目录、链接和虚拟文件不支持。接收文件存入数据目录的 data/sync-files，使用或再次发送时校验大小和 SHA-256。改动或删除托管文件会使恢复校验失败，不应手工整理该目录。

应用内导出/导入和目录迁移会携带这些文件；路径按相对位置重建。删除条目后，无引用的接收目录保留至少十分钟，再由后台定期回收。

设备身份、配对和 WebDAV 凭据单独由 Windows DPAPI 保存到 %LOCALAPPDATA%/QcClipDevice/sync.bin，不随内容数据导入覆盖。该文件绑定当前 Windows 用户；不要把它复制到其他电脑作为配对方式。首版界面提供撤销配对；丢失身份文件后将生成新身份，必须在对端撤销旧设备并重新配对。

首次使用新版会将数据库升级到 schema 2，保留已发布 schema 1 数据。升级后仍可回退旧版本继续使用，旧版期间新增的内容在再次升级后保留；清理历史、整理数据等重写操作需使用新版。

主窗口回归有实际断言，需要 GPUI 桌面会话，默认跳过。在具备桌面环境时单独运行：

```powershell
cargo test --bin QcClip windows::main::state::sync::tests::remote_updates_preserve_browsing_and_only_update_related_rows -- --ignored --exact --nocapture
```

人工界面预览和依赖个人测试服务器的临时入口不作为最终自动测试保留。Clippy 命令中的两项放行针对仓库已有的重复条件和等式除法诊断；不能据此宣称仓库已消除全部警告。全量测试若涉及既有排序断言等失败，应与同步专项结果分别记录。

跨电脑实机需单独验收：附近发现及防火墙、双方配对确认、LAN 优先及断开后转 WebDAV；坚果云实际额度和持续请求量；自建服务 1–2 秒检查；离线后拉取、缓存淘汰、大资源与小文本并行接收；撤销、关闭通道、导入数据和文件迁移。本机 HTTPS 回归不能替代这些网络及厂商验收。

## 与数据包的区别

日常同步传递新增内容，WebDAV 缓存受条数和容量限制。需要完整转移收藏、按需备份或在另一设备覆盖指定数据时，使用“设置 → 数据管理 → 数据转移与备份”。本地与 WebDAV 使用相同数据包，支持独立密码和导入预览、合并、替换；不需要设备配对，也不要求开启自动同步。云端包不轮询、不参与同步缓存淘汰。详见[数据转移与备份](data-packages.md)。
