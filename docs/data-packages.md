# 数据转移与备份

## 入口与日常操作

打开“设置 → 数据管理 → 数据转移与备份”，选择“导出数据”“导入数据”或“云端数据包”。三种操作使用同一个侧边抽屉，不改变跨设备同步页面的日常上传、拉取行为。

例如，把家里的收藏带到公司：

1. 在家里的设备导出，勾选收藏，选择保存到 WebDAV。可按标签筛选收藏；不选标签表示全部收藏。
2. 可选用独立密码加密，上传完成后关闭抽屉。
3. 在公司的设备打开云端数据包，刷新列表，下载并预览；加密包需要输入导出时的密码。
4. 勾选收藏，选择“替换所选数据”并确认，导入后公司的历史、图库和设置保留。

WebDAV 只需在跨设备同步页保存地址与账号；数据包不需要设备配对，也不要求开启自动同步。列表只在打开云端页、手动刷新时查询，不轮询。用户也可以通过本地文件传递完全相同的 `.qcclip-data` 数据包。

## 数据范围与冲突规则

| 范围 | 导出选择 | 合并 | 替换 |
| --- | --- | --- | --- |
| 收藏 | 全部或包含任一所选标签的收藏 | 按内容去重，补充收藏关系和标签；已有备注、排序、统计保留 | 清空本机收藏关系，采用包内收藏、顺序、标签和备注 |
| 历史 | 全部或最近 1–36500 天，以最后捕获时间为准 | 按内容去重，新条目追加，已有记录保留 | 清空本机历史关系，采用包内历史、顺序、标签、备注和统计 |
| 图库 | 全部组及图片 | 同名组合并，同名且内容不同的图片另存文件，重复导入不重复新增 | 整体替换图库 |
| 应用设置与提示音 | `config.json` 和 `sound` | 设置文件整体覆盖，提示音文件补充/覆盖 | 同左 |

导入只处理勾选的范围。筛选包的“替换”仍然替换所选范围的**全部**本机内容，不按标签或天数缩小本机清空范围，界面会明确提示并要求确认。

历史和收藏共用内容、标签、备注；替换包内某条内容的标签和备注，也会影响这条内容在另一列表中的显示。未勾选范围的列表关系不会被删除。替换通过关系重建完成，不承诺物理安全擦除。

图片原始字节、应用图标以及接收同步文件时产生的受管理附件会随对应条目打包。普通文件条目只保存路径，不读取原路径中的用户文件。应用设置不包含设备身份、配对或 WebDAV 凭据；普通导出不包含窗口状态、日志、暂存目录及历史备份。

导入不发送同步事件，不逐条改写系统剪贴板。导入结束后热加载列表及配置，无需重启。

## 独立密码与格式

新包使用 `QCCLIPPKG2\n` 格式头，随后是加密标识及压缩归档。解包仍支持已发布的 `QCCLIPDATA1\n` 归档，旧包也可预览并按范围合并或替换。

- 未加密：Zstd 压缩归档，包含清单和逐文件 SHA-256。
- 加密：Argon2id v1.3，64 MiB 内存、3 轮、1 路并行，由独立密码与随机 16 字节盐派生 32 字节密钥。
- 使用 XChaCha20-Poly1305，1 MiB 分块。随机 16 字节前缀与分块序号构成 nonce；格式头、分块序号和终止标记作为附加认证数据。独立认证的结束块用于检测截断，拒绝多余尾部。
- 清单、数据范围、条目数和正文均位于加密内容内。密码不写盘，不与同步密钥共用；密码丢失无法恢复。
- 文件数最多 100 万，单文件最多 4 GiB，总内容最多 64 GiB。检查路径越界、重复路径、文件哈希、数据库结构、完整性、外键以及资源引用和内容。

压缩、加解密、归档和上传使用临时文件、分块读写，避免一次把完整数据包读入内存。加密仅保护最终数据包，运行时数据库、解包临时目录和本机自动备份不属于静态加密存储。

## 一致性、备份与失败处理

导出在 `data_runtime` 独占操作内使用 SQLite Backup API 建立快照并复制所选资源。压缩、加密和网络传输在释放独占锁后进行。筛选后的数据库会执行 VACUUM，避免已排除记录残留在数据库空闲页。

导入先在临时目录解密并校验。用户确认后，独占复制当前数据，在当前数据根目录的 `.package-backups/before-import-<UUID>.qcclip-data` 保存本机未加密备份；随后在快照上合并，验证成功才交给原有可回滚的暂存替换流程。切换锁保持到配置热加载完成。

“查看导入前备份”会打开备份目录，可重新选择包并导入相应范围。备份不会自动上传、自动轮换或递归包含在下次导出中，请按需要自行保留或删除。旧版迁移的自动备份仍位于数据目录旁的 `<数据目录名>-migration-backups`，也可从导入入口恢复。

错误密码、损坏文件和合并失败不会应用到本机数据。暂存标记写入后若程序退出，下次启动会继续原有导入流程；文件替换失败时会尝试回滚并报告具体失败阶段。回滚成功后，将失败暂存保留在 `.package-backups/failed-import-<UUID>`，撤销等待状态，允许直接重新导入，避免重启后反复应用旧快照。回滚失败时保留恢复现场，不自动清理。启动恢复失败也会显示全局错误通知。快照、备份、压缩及解包均需要额外磁盘空间。

## WebDAV 存放与请求

包位于配置地址下的 `qcclip-v1/packages/`，名称为 `qcclip-<毫秒时间>-<随机 UUID>.qcclip-data`。列表只公开文件名、时间和大小，不在服务器另存明文内容索引。

上传使用两个 MKCOL（允许目录已存在）和一个流式 PUT；刷新列表使用一次 Depth 1 PROPFIND；下载使用一次流式 GET；删除使用一次 DELETE。没有索引下载、逐条对象下载或定期探测；两个设备上传不同随机名称的包，不覆盖共享索引。请求仍计入本次运行的 WebDAV 请求统计，并遵循服务器的 429/503 冷却。

使用 HTTP WebDAV 时，账号密码与访问路径不加密；未加密的数据包内容也可能被链路第三方读取。

数据包独立于 `indexes/`、`objects/` 的在线同步缓存，不受缓存条数、容量和淘汰规则影响。大包传输限制连接和读写停顿，不沿用小型同步请求的三分钟总时限。

## 验证

```powershell
cargo test --bin QcClip services::data_management
cargo test --bin QcClip i18n::tests
cargo test --bin QcClip services::sync
```

专项测试覆盖收藏替换与备份恢复、合并去重、只导入勾选范围、标签和日期筛选、图库冲突与替换、独立密码与损坏包、已发布归档兼容、路径攻击和本机模拟 WebDAV 的实际请求序列。未使用真实用户数据或云端账号。
