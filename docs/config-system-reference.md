# QcClip 配置系统

本文说明配置的存储、加载和运行时更新规则。配置模型与默认值以 [src/config/mod.rs](../src/config/mod.rs) 为准，数据库结构见 [数据库设计](database-design.md)。

## 职责与文件

| 模块 | 职责 |
| --- | --- |
| [src/config/mod.rs](../src/config/mod.rs) | 配置模型、schema 版本、默认值、枚举和规范化 |
| [src/config/load.rs](../src/config/load.rs) | 字段级 JSON 加载和诊断 |
| [src/config_runtime.rs](../src/config_runtime.rs) | GPUI 全局配置、原子保存、类型化更新和运行时应用 |
| [src/app_paths.rs](../src/app_paths.rs) | 数据目录及配置、状态、数据库等路径 |
| [src/state_runtime.rs](../src/state_runtime.rs) | 独立的应用状态持久化 |
| [src/windows/settings/](../src/windows/settings/) | 设置控件与配置更新入口 |

配置模型不依赖 GPUI、窗口或数据库连接。设置控件通过 `config_runtime` 的类型化接口读取和更新配置，不直接读写 JSON。

应用数据根目录中的主要文件如下：

| 文件 | 保存内容 |
| --- | --- |
| `config.json` | 用户设置 |
| `state.json` | 窗口位置和尺寸、当前标签页、表情与符号最近使用记录、图库排序、便签与最近使用的便签偏好等恢复状态 |
| `qcclip.sqlite3` | 剪贴板内容、格式、历史、收藏、标签和备注 |
| `config.updates.json` | 更新检查时间、最新版本和已通知版本，由更新服务单独管理 |

搜索输入、滚动位置、加载任务和图像缓存等临时状态由窗口维护，不属于配置文件。

`state.json` 的 `sticky_preferences` 保存最近调整的便签颜色（`color`，为空时跟随主题）、置顶开关（`topmost`）、不透明度（`opacity`，范围 0.3～1.0），以及拆词粒度（`granularity`）、保留符号开关（`include_symbols`）和拼接方式（`separator`）。调整后立即保存，新建普通便签或通过“拆词”打开新便签时继承这些偏好；关闭全部便签后仍保留。`sticky_notes` 同时记录各张便签自己的这些选项，重启时分别恢复；窗口位置、尺寸、折叠和拆词界面状态仍按便签保存。

跨设备同步设置由独立的 [services/sync/config.rs](../src/services/sync/config.rs) 管理，不写入 `config.json` 或 `state.json`。Windows 上的设备身份、配对、发送序号、连接及设备策略和 WebDAV 凭据统一通过 DPAPI 保护，保存于 `%LOCALAPPDATA%/QcClipDevice/sync.bin`，不使用 Windows 凭据管理器，不随内容导入或数据目录迁移覆盖。清理日志 `sync-cache-*.json` 仅保存待回收对象的随机标识。配置语义见[同步使用说明](sync-guide.md)。

托盘菜单中的“格式粘贴”保存为 `config.json` 的 `clipboard.formattedPaste`，默认开启。关闭后默认粘贴和合并粘贴都优先只粘贴纯文本，条目没有纯文本时按原格式粘贴；文件和图片合并保持原样。右键菜单指定格式粘贴和复制操作不受影响。

标签面板中的“切换页面时清空选择”保存为 `config.json` 的 `clipboard.clearTagsOnTabSwitch`，默认关闭；开启后切换到历史或收藏页面时清空标签选择。

## 配置分组

首发配置 schema 版本为 **1**。JSON 字段使用 camelCase，顶层版本字段为 `schemaVersion`。

| JSON 分组 | 内容 |
| --- | --- |
| `general` | 中英文界面、全局通知、开机自启和管理员启动 |
| `clipboard` | 原生格式读取名单、鼠标操作、显示与预览优先级、悬停预览、粘贴排序、搜索行为、窗口呼出位置、贴边隐藏和搜索引擎 |
| `applicationFilter` | 指定应用及其剪贴板监听、全局快捷键和贴边隐藏禁用规则 |
| `history` | 历史保留天数和最大条数 |
| `quickPaste` | 便捷粘贴窗口的条目数、宽度、方向键行为和位置记忆 |
| `sound` | 粘贴、复制和便捷粘贴滚动的音效与音量 |
| `appearance` | 明暗模式、主题 ID、界面缩放、窗口材质、背景图片、透明度、列表样式和动画 |
| `shortcuts` | 全局快捷键、快捷粘贴 1～9 和窗口操作快捷键 |
| `updates` | 检查频率、自动下载（`autoDownload`，默认开启）、更新通知和代理 |

默认值由各配置类型的 `Default` 提供，加载与更新时按相应模型规则规范化。设置页不维护另一套默认值。

`clipboard.captureFormats` 包含 `all` 开关和原生格式名称数组 `names`。默认只读取常规格式；名单支持增删和恢复默认，空名单表示不捕获新内容。全量模式保留名单，关闭后继续使用。保存成功后更新后台快照，下一次捕获生效，读取系统剪贴板时不持有配置锁。读取与延迟渲染处理见 [Windows 剪贴板实现](../src/platform/clipboard.rs)。

主窗口列表支持 `single`（单栏）、`side-by-side`（左右双栏）和 `stacked`（上下双栏），可在“设置 → 主窗口”或标题栏更多菜单切换。普通窗口使用 `clipboard.listLayout`，默认单栏；贴边窗口使用 `clipboard.edgeListLayouts`，按左右贴边、上下贴边分为两组，默认分别为上下双栏、左右双栏。三组布局独立保存，切换定位后恢复各自偏好，均可选择单栏或任一种双栏方向。双栏同时显示剪贴板与收藏，共用搜索、类型筛选与标签筛选，分别保留滚动和选择状态；鼠标进入列表或使用切换列表快捷键选择当前操作列表。两栏不显示独立标题，当前操作列表以主题色顶部边框标记。上下贴边保留横向卡片列表，左右贴边使用纵向列表。普通窗口的左右与上下双栏分别记忆尺寸，默认客户区大小为 860×560 和 420×760；贴边窗口沿屏幕边缘铺满，厚度仍按每条边独立记忆，最大不超过屏幕对应方向的一半。

双栏中间的分隔条使用与窗口标题栏一致的背景色，可拖动调整比例，剪贴板列表占比限制为 20%～80%，双击分隔条恢复均分。拖动到均分位置两侧 1% 范围内会吸附到 50%，吸附后拖出 1.5% 范围即可解除。普通窗口的左右、上下布局比例分别保存在 `state.json` 的 `main_window.split_ratios` 中；贴边比例保存在 `main_window.edge_split_ratios`，左右贴边与上下贴边分别记忆两种双栏方向的比例。松开鼠标时保存，切换布局或重启后恢复。拖动期间保持当前操作列表，拖动分隔条或任一列表的热度滚动条时暂停贴边自动收起。

`clipboard.previewTypes` 保存悬停预览允许显示的类型，支持 `text`、`html`、`image` 和 `file`，默认全部启用。关闭某一类型只影响悬停预览候选，不会删除已保存的剪贴板格式，也不影响列表显示、搜索或粘贴。

历史保留限制只控制历史列表的可见范围，置顶历史豁免；收藏使用独立收藏关系。超出范围的历史在主动清理前可通过扩大范围重新显示。

## 加载与保存

`config/load.rs` 先将 JSON 解析为 `serde_json::Value`，再逐组、逐字段读取，返回配置及警告列表。`ConfigRuntime` 统一记录中文警告。

| 输入情况 | 加载行为 |
| --- | --- |
| 文件不存在 | 使用默认配置，成功保存时创建文件 |
| 文件无法读取 | 记录警告并使用默认配置启动 |
| JSON 无效或根节点不是对象 | 记录警告并使用默认配置启动 |
| 分组类型错误 | 该分组使用默认值，其他分组继续读取 |
| 单字段类型错误或枚举值未知 | 该字段使用默认值，保留其他有效字段 |
| 字段缺失 | 使用字段默认值 |
| 未知字段 | 不参与运行时配置，保存时保留原始字段 |
| `schemaVersion` 缺失或无效 | 运行时使用当前 schema 版本；无效值记录警告 |
| `schemaVersion` 高于当前版本 | 按已知字段加载，保存时保留更高的版本号 |

保存时重新读取现有文件，只合并实际变化的已知字段，保留未知字段和未修改字段的原始值，包括未知枚举值。已有文件无法读取、JSON 无效或根节点不是对象时，停止保存并返回错误，避免覆盖原数据。

修改已知字段会替换该字段的原始值；整体替换数组等字段时，不保证保留其中未知的内部结构。保留未知字段并不代表旧程序能够理解新版本的全部语义。

普通配置更新顺序为：

```text
读取当前配置
  -> 构造候选配置并按字段规则规范化
  -> 判断是否变化
  -> 合并原文件并原子写盘
  -> 写盘成功后替换内存配置
  -> 应用运行时变化并刷新窗口
```

持久化使用 `atomic-write-file`，写入格式化 UTF-8 JSON 并追加换行。写盘失败时保留内存旧值，由设置页报告错误。重复设置相同值不产生无意义写入。

开机自启、管理员启动和快捷键还涉及系统能力，须通过现有运行时入口处理其执行结果与回滚，不能仅修改 JSON。快捷键期望值保存在配置中，注册状态由快捷键运行时维护。

## 启动与热更新

[src/app.rs](../src/app.rs) 在 GPUI 和组件初始化后安装 `ConfigRuntime`，随后安装独立的状态运行时，并使用配置初始化音效、语言和主题，再创建窗口。因此窗口首次显示时已经使用保存的语言与外观。

语言保存成功后调用现有 i18n 运行时并刷新窗口。主题由 [src/ui/theme.rs](../src/ui/theme.rs) 解析和应用：

- `system` 模式跟随系统外观，`light` 和 `dark` 模式保持用户指定的明暗模式。
- 配置保存主题 JSON 中稳定的 `themes[].name`，设置页使用本地化显示名。
- 找不到主题 ID 时，通过主题运行时选择对应模式的默认或可用主题。

`appearance.uiScalePercent` 保存界面缩放百分比，默认 100，范围为 80～200。设置保存后立即刷新所有窗口，切换主题时从主题原始字号重新应用比例。界面文字、图标和控件尺寸随比例调整；系统 DPI、桌面坐标与图片原始尺寸独立计算。

`appearance.previewScalePercent` 保存悬停预览窗口的额外缩放百分比，默认 100，范围为 80～200，在“列表与预览”设置页调整。预览窗口的 rem 基准为 `16 × 界面缩放 × 预览缩放`，正文、备注、信息栏和文件信息随之调整；图片显示尺寸由预览内的缩放操作单独控制，不受此项影响。修改后刷新窗口，预览在下次绘制时按新尺寸重新换行和布局。

`appearance.itemDisplay` 控制主窗口剪贴板和收藏条目的首行信息及右上角控件，与行高独立。`infoVisibility` 控制首行信息，`toolbarVisibility` 控制右上角的来源图标和序号，`actionsVisibility` 独立控制右上角的操作按钮。三组均支持 `always`（始终显示）、`active`（悬停或选中）、`hidden`（隐藏）；`fields` 保存启用的具体信息和按钮。默认首行、来源和序号常显，操作按钮在悬停或选中时展开，全部字段启用。

“列表与预览”设置页中的“条目信息与操作”提供默认、纯净、精简、完整预设及逐项配置。默认恢复上述显示组合；纯净隐藏全部三组；精简隐藏首行，来源和序号常显，悬停或选中时显示收藏、置顶和删除；完整常显全部信息和适用操作。布局仍为首行和右上角两个区域。首行隐藏或时间和长度均关闭时，不保留信息行高度；首行按需显示保留布局占位，操作按钮按需展开或收起。右键菜单和快捷键不受显示配置影响。

新增设置项须同时接入模型默认值、加载器、必要的规范化、运行时读取与更新、设置页和相关验证。运行时状态不应混入用户配置。

## 数据目录与导入

安装版由 `AppPaths` 发现默认数据目录，固定宿主目录中的 `location.json` 可指定实际数据根目录。配置、状态、数据库、原始字节、图库、音效和日志使用同一数据根目录。

程序同级存在 `QcClip.portable` 文件时，数据固定保存到程序目录下的 `QcClipData`，不使用安装版的位置定位文件。便携版禁用数据位置更改和开机自启，详见 [打包说明](packaging.md)。

更改数据位置或导入归档时，[数据管理服务](../src/services/data_management.rs) 通过 [data_runtime](../src/services/data_runtime.rs) 暂停受管理数据操作，等待现有操作结束，再替换文件并热加载配置、状态和相关服务。配置保存参与同一操作协调，数据切换期间返回错误。

数据包支持按范围导出、独立密码加密以及本地或 WebDAV 保存。导入先校验和预览，再按勾选范围合并或替换，应用前保留本机备份；选择应用设置时整体覆盖 `config.json`，窗口状态和独立设备身份保留。已发布旧归档仍可导入。暂存完成后若程序退出，下次启动继续应用，无需手动重启。详情见[数据转移与备份](data-packages.md)。

## 版本与兼容规则

配置 schema 与数据库结构、数据库读写协议分别维护，不能混用版本号。

以正式发布版本的 Git Tag 为兼容边界：已发布 schema 的语义变更须评估并提供明确迁移，迁移失败须保留原文件。正式 Tag 之后、下一次正式发布前的开发变更可直接修改，不维护开发阶段迁移链。

涉及字段删除、含义变化或存储编码变化时，不能依靠默认值回退代替迁移。迁移验证应使用正式 Tag 对应的配置样本，并核验高版本文件中的未知字段和版本号不会被旧程序无意覆盖。

## 验证入口

配置模型、字段级加载和持久化的测试位于相应源码模块。可运行：

```powershell
cargo test --locked config::
cargo test --locked config_runtime::tests
cargo test --locked --test app_paths
cargo test --locked --test data_runtime
```

语言切换、系统主题变化、保存失败提示、快捷键注册，以及导入和目录切换后的窗口刷新还需要实际界面验证。更新检查的行为与测试入口见 [版本更新检查](update-check.md)。
